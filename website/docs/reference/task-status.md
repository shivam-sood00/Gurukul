# Task Status

This catalog names every registered Gurukul Gym task. It reports repository evidence, not an expected outcome.
A task can be registered and have an agent configuration while still lacking a simulator smoke run, a converged policy,
or transfer validation.

## How To Read The Catalog

- **Registered** means a static `gym.register(...)` surface exists. It does not mean the environment has launched.
- **Agent config only** means the registration exposes an RL agent or trainer configuration. It does not establish that
  training starts, remains numerically healthy, or converges.
- **CPU algorithm smoke** exercises tensor-level rollout/update code without launching Isaac Sim.
- **Static contract tests** inspect source, configuration, shapes, assets, or saved interfaces without proving a simulator
  rollout.
- **Artifact** refers to a task-compatible policy checkpoint or export. Motion clips and robot assets are not policy
  artifacts. **None bundled** still allows users to train and export their own policy.
- **Transfer adapter** means a runner/configuration exists. It does not establish a successful MuJoCo rollout.
- **Hardware runner** means executable integration code exists. No row claims physical-robot exercise unless stated
  explicitly; this catalog currently records none.

The conservative phrases in the table are intentional. Follow the linked guide for prerequisites and exact commands.
Some tasks that consume external motion data, the composed Go2+D1 model, or the local OmniPerception integration
additionally require files excluded from the public checkout. Installation is documented on the corresponding
[motion-data](../tasks/apex/motion-data), [Go2+D1](../tasks/quadruped-with-arm/go2-d1-wbc), and
[LiDAR](../tasks/lidar-based) pages. Gurukul's authored Go2+D1 APEX motions are included, but their tasks still require
the local D1 geometry-bearing USD. The lidar task is registered only when its optional local runtime module is present.
