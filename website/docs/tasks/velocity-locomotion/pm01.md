# EngineAI PM01 Velocity

PM01 flat and rough velocity locomotion use the retained official 24-DoF USD with EngineAI's authored black, silver,
white, and orange/red materials. Every revolute joint is controlled, including `J23_HEAD_YAW`. The actuator gains,
armatures, effort and velocity limits, and action scales are shared with the official EngineAI BeyondMimic
configuration.

## Train

Train flat locomotion:

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task=Gurukul-Isaac-Velocity-Flat-EngineAI-PM01-v0 \
  --num_envs 16384 \
  --logger wandb \
  --headless \
  --run_name engineai_pm01_official_urdf_flat_ppo
```

Train flat velocity following with EngineAI's AMP walking prior:

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task=Gurukul-Isaac-Velocity-Flat-EngineAI-PM01-AMP-v0 \
  --num_envs 16384 \
  --max_iterations 10000 \
  --logger wandb \
  --headless \
  --run_name engineai_pm01_amp_walk
```

Train rough-terrain locomotion:

```bash
python scripts/reinforcement_learning/rsl_rl/train.py \
  --task=Gurukul-Isaac-Velocity-Rough-EngineAI-PM01-v0 \
  --num_envs 16384 \
  --logger wandb \
  --headless \
  --run_name engineai_pm01_official_urdf_rough_ppo
```

Runs are written under `logs/rsl_rl/engineai_pm01_official_urdf_flat/`,
`logs/rsl_rl/engineai_pm01_official_amp_flat/`, and `logs/rsl_rl/engineai_pm01_official_urdf_rough/`.

The AMP task retains the flat velocity task's command-conditioned rewards and 24-action actor. Its discriminator sees
five frames of EngineAI's legacy 23-joint state plus base-frame linear velocity; head yaw remains an actor action but is
not part of the legacy reference. The bundled 100 Hz `locomotion.npz` comes from EngineAI's BSD-3-Clause
[`engineai_amp`](https://github.com/engineai-robotics/engineai_amp) repository. The maintained actor runs at 50 Hz, so
the loader uses every second reference frame. The AMP checkpoint stores the discriminator and its optimizer so resumed
training preserves the learned style reward.

### AMP prior

The style prior is live from the first iteration at `amp_style_reward_weight = 2.0`, which reproduces upstream's
per-second prior strength (upstream adds `0.01 * 2.0 * style` per step at 100 Hz; Gurukul scales by the 50 Hz
`policy_dt`). Against this task's roughly 5 reward/s that is worth up to about 30% of the total return. The warm-up and
ramp knobs remain on `EngineAiPm01AmpAlgorithmCfg` but default to zero; a warm-up long enough for PPO to converge first
only perturbs a settled policy.

Two properties of the released clip shape the configuration:

- **Speed support.** EngineAI's 23 s capture is a short stand, roughly 13 s of walking at 0.25--0.94 m/s, then about
  8.5 s of standing still. `amp_reference_min_speed = 0.15` drops the static frames, because the AMP observation
  carries no velocity command and a prior that rates standing as expert rewards freezing under a walk command. The
  prior has no support above roughly 1.0 m/s forward or 0.3 m/s lateral, while `base_velocity` commands reach 1.5 and
  0.5 m/s; narrowing `EngineAiPm01CommandsCfg.ranges` to the clip's envelope is the next lever if style and tracking
  fight each other.
- **Nominal pose.** The discriminator reads absolute joint positions, so the AMP task adopts the clip's arm pose
  (`PM01_AMP_REFERENCE_ARM_POSE`) as the robot's nominal pose. The maintained PM01 pose sits 8--15 standard deviations
  from the reference on shoulder yaw, elbow yaw and shoulder roll, which lets the discriminator separate expert from
  policy on posture alone. This also moves the action offset and the `variable_posture` target, so an AMP checkpoint
  has a different nominal pose from the plain velocity checkpoint and must be exported and deployed separately.

Start a fresh run when changing the schedule: resuming a checkpoint also restores the AMP update counter.

What to watch:

| Signal | Healthy | Meaning |
| --- | --- | --- |
| `Metrics/amp_style_raw` | 0.3--0.9 | Unweighted discriminator reward. Pinned near 0 means the discriminator has saturated and the prior carries no gradient whatever the weight. |
| `Loss/amp_expert_score` / `Loss/amp_policy_score` | roughly +0.5 / -0.5 | Near +1 / -1 is a saturated discriminator: shrink `amp_discriminator_hidden_dims`, raise `amp_discriminator_update_interval`, or raise `amp_gradient_penalty_scale`. |
| `Step_Reward/amp_style` vs `Step_Reward/task` | 10--40% | The prior's actual share of the return. |
| `Metrics/base_velocity/error_vel_xy` | falling | If it rises as the prior engages, the prior and the commands disagree; narrow the command ranges. |
| `Episode_Reward/feet_air_time` | approaching 0 | The reference gait is a 1.31 s cycle with roughly 0.55 s of swing per leg, so the 0.5 s `feet_air_time` threshold matches the prior. |

## Xbox playback

Connect the controller before launching Isaac Sim, then play a trained AMP checkpoint with:

```bash
python scripts/reinforcement_learning/rsl_rl/play.py \
  --task=Gurukul-Isaac-Velocity-Flat-EngineAI-PM01-AMP-v0 \
  --num_envs 1 \
  --gamepad
```

The runner selects the latest matching checkpoint; use `--checkpoint <path>` to select one explicitly.
The left stick commands forward/backward and left/right velocity; the right stick commands turning. Releasing the
sticks commands zero velocity. Inputs scale to the task's training ranges, including the different forward and
reverse limits. The command arrow shows the requested velocity. Use `--gamepad-deadzone 0.12` if the sticks drift
(default: `0.08`).

`--keyboard` selects keyboard input only; use `--gamepad` in its place for Xbox input. Gamepad playback uses the
first controller recognized by Isaac Sim, runs one environment, and requires the GUI. See
[Xbox controller recognition](../../reference/cli-reference.md#xbox-controller-recognition) for the Linux USB mapping.
The command wiring is covered by simulator-free regression tests; physical-controller playback has not been validated.

## MuJoCo Sim2Sim

The velocity actor has 1,173 observations and 24 actions. Five actor terms have 15-frame histories; the current
3-D velocity command is inserted between projected gravity and joint position. Both training and deployment run the
low-level simulation at 500 Hz and the policy at 50 Hz. The training critic has 1,218 observations, including a
15-frame history of the privileged base linear velocity.

After exporting a trained ONNX policy, run it against EngineAI's official native-SDK MuJoCo scene:

```bash
python engineai-sim2real/RL_policy_runner/sim2sim/run_pm01_policy.py \
  --policy-path logs/rsl_rl/engineai_pm01_official_urdf_flat/<run>/exported/policy.onnx \
  --launch-mujoco \
  --mujoco-viewer native
```
